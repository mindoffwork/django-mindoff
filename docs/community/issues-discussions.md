# Issues & Discussions

The project uses GitHub Issues and Discussions to track bugs, feature requests, and community questions.

Using the correct channel helps keep the project organized and ensures that reports and ideas are addressed effectively.

## Reporting Bugs

If you encounter a bug while using django-mindoff:

1. Search existing Issues to check if the problem has already been reported.
2. If not, create a new Issue.
3. Provide clear and detailed reproduction steps.

Helpful information to include:

- django-mindoff version
- Django version
- Python version
- Minimal reproducible example
- Stack trace or error message

Clear reports make it easier to diagnose and resolve problems quickly.

## Requesting Features

Feature requests are welcome.

When proposing a feature, include:

- The problem you are trying to solve
- Why the feature would be useful
- Possible approaches or ideas for implementation

Feature discussions help evaluate ideas before implementation.

## Questions and Usage Help

If you have questions about how to use the framework, open a discussion on GitHub instead of creating an issue.

Discussions are intended for:

- Usage questions
- Architecture discussions
- Best practices
- General feedback

This keeps the issue tracker focused on actionable bugs and improvements.

## Best Practices

To help maintain a healthy project workflow:

- Search before opening a new issue
- Provide clear and reproducible examples
- Keep discussions constructive and respectful
- Follow the project's Code of Conduct
